## P0 — fix before anything else

- [x] **DONE (0.2.3).** **`translate_error/1` crashes on non-stringable error opts**
  (`lib/joby_kit/core_components.ex:617`). Eager `to_string(value)` in the
  `String.replace/3` instead of the lazy `fn _ -> to_string(value) end` form.
  **Verified live**: `translate_error({"is invalid", [type: {:array, :string},
  validation: :cast]})` — the exact opts Ecto attaches to every cast error on
  an array field — raises `Protocol String.Chars not implemented for Tuple`.
  Every `field={...}` input pipes errors through this, so any host with an
  `{:array, _}` or composite-typed field 500s on the first invalid submit.
  Invisible to the suite (tests only use stringable opts). One-line fix +
  regression test.

## P1 — major, fleet-visible

### New: a stale global Mix archive shadows the project dep (found 2026-08-10
while verifying the 0.2.3 template changes)

`mix archive` lists **`joby_kit-0.2.0`** installed globally. Mix resolves
`Mix.Tasks.JobyKit.Install` from the archive, not from the project's
dependency, and the archive carries its own `priv/templates` — so
`mix joby_kit.install` in *any* project generates **v0.2.0 scaffolding
regardless of what that project's `mix.exs` pins**. Reproduced directly:
with the path dep on the 0.2.3 tree and the new nine-component template
on disk, the installer wrote the old five-component manifest; re-running
changed nothing. Verifying the new templates required rendering them
with EEx by hand to bypass the archive.

Consequences: the 0.2.3 manifest registrations (and every future
template fix) silently do not reach hosts that run the installer; this
also plausibly explains generated-file drift across the fleet, since
apps were scaffolded by whatever archive version was installed that day.

- [x] **DONE — split the package.** `joby_kit.new` and its templates now
  live in a separate `joby_kit_new` package
  (<https://github.com/JobyCorp/joby_kit_new>), the same arrangement
  Phoenix uses for `phx_new`. The archive no longer contains the
  in-project tasks, so it has nothing to shadow — the failure mode is
  structurally impossible rather than detected. The version-guard option
  was rejected because Mix offers no way to prefer the dep's task over an
  archive's, so a warning would dead-end the user.
  Root cause for the record: only `joby_kit.lint` declared
  `@requirements ["compile"]`, which loads the project's deps first and
  so resolved to the dep. The other tasks declared none, so the archive
  answered.
- [x] **DONE — no longer needed.** The archive now only carries the
  generator, so it can go stale without affecting what any project
  generates. jody's workstation has been switched to
  `joby_kit_new-0.3.0`; the combined `joby_kit` archive is uninstalled.
- [x] **DONE — obsolete.** `joby_kit.install` templates ship in the kit
  dependency, so a template change is delivered by the hex release
  itself. Only `joby_kit.new`'s own templates live in the archive, and
  those release with `joby_kit_new`.

### New: starter app was not kit-compliant (found 2026-08-11 doing a design pass)

The app `mix joby_kit.new` generates is the kit's own worked example, and
an agent told "build UI like the rest of this app" will copy it. It was
not following the contract:

- [x] **DONE.** The landing page hand-rolled its header, nested a second
  `<main>` inside the layout's, and styled sections with one-off classes.
  Rebuilt from wrappers; each section now names the component rendering it.
- [x] **DONE.** No theme switching at all. `joby_kit.new`'s
  `root.html.heex` had dropped the pre-paint theme script `mix phx.new`
  ships, while `app.css` still defined both themes — so the light theme
  was unreachable. Restored, plus a registered `theme_toggle/1`.
- [x] **DONE.** Tailwind cannot see interpolated class names. The first
  cut of `theme_toggle/1` built its active-state variant with
  `"[data-theme=#{theme}]..."` (interpolated), which compiled to a literal
  `#{theme}` rule — the control rendered but never highlighted. Caught in
  the browser, not by tests; now pinned by one. Worth remembering as a
  class of bug: **never interpolate into a class name.**
- [x] **DONE.** Long attr defaults collided with the attr name in
  signature cards.

### Core components (`lib/joby_kit/core_components.ex`)

- [x] **DONE (0.2.3).** **`<.button type="button">` silently dropped** (line 79). `type` is not
  a declared attr, not in the `:rest` include list, and not a Phoenix global.
  Every button inside a form is `type="submit"` with no opt-out — a
  Cancel/Toggle button submits the form. Inherited from Phoenix 1.8's
  generator; add `type` to the include list.
- [x] **DONE (0.2.3).** **Simultaneous flashes overlap** (line 339). Each flash renders its own
  fixed-position daisy `toast toast-top toast-end` container, so
  `put_flash(:info) |> put_flash(:error)` (and the disconnect toasts) paint
  at the same spot and occlude each other. Move the `toast` container into
  `flash_group/1`, render alerts inside it.

### Manifest template

- [x] **DONE (0.2.3).** **Install manifest registers only 5 of 9 shipped components**
  (`priv/templates/joby_kit.install/design_manifest.ex:39-67`). `header`,
  `list`, `table`, `flash_group` are shipped, documented in the
  CoreComponents moduledoc, and named in the template's own comment — but

### Linter (`lib/joby_kit/lint.ex`)

- [x] **DONE (0.3.0).** **Whole-file wrapper-territory exemption is leaky and gameable**
  (lines 295-297). Any file containing the substring `data-component=`
  anywhere — comment, docstring, non-root element — exempts every raw
  primitive in the file. One wrapper in a 500-line LiveView zeroes coverage
  for the rest; a `# data-component=` comment silences the linter without
  the documented allow-marker audit trail. Fix direction (reported
  independently by mem_pal, see C5): scope the exemption per wrapper
  `def`, not per file.
- [x] **DONE (0.3.0).** Only the first primitive per line is reported
  (`Regex.run` not `scan`) — `<input /><select />` yielded one violation.
- [x] **DONE (0.3.0).** Commented-out markup is flagged (false positive):
  `<%!-- <button> --%>` and `<!-- ... -->` fire the rule. Comments are now
  blanked (newlines preserved) before scanning, and the allow-marker is
  read from the original text since it is itself a HEEx comment.
- [x] **DONE (0.3.0).** `@sigil_h_re` misses `~H'''` single-quote heredocs —
  such files were never scanned.
- [x] **DONE (0.3.0).** Violation message recommended `# jobykit:allow-raw-html`
  "on the preceding line", but inside a `~H` block a `#` line is literal
  template text that renders into the page. The message now says so.
- [x] **DONE (0.3.0).** `<Input.autocomplete>`-style remote components named
  `Input`/`Select`/`Button` false-positived against the case-insensitive tag
  regex. Now case-sensitive, which matches HEEx semantics: lowercase is HTML,
  capitalised is a component.
- [ ] `:missing_data_component` is a whole-file `String.contains?`
  (lines 128-151): docstring occurrences pass the check (false negative),
  dynamic `data-component={@dc}` fails it (false positive).
  **Confirmed live 2026-08-10**: a clean install of the shipped
  `composite_components.ex` template lints with one phantom
  `unregistered_wrapper` warning for
  `JobyKitDevWeb.CompositeComponents.<name>` — the regex matching the
  contract description in the module's own docstring. Every freshly
  installed host starts with a false-positive warning.

### NavPatcher (`lib/joby_kit/nav_patcher.ex`)

- [x] **DONE.** The search is now bounded to the enclosing nav/header, so a
  nav we can't place links inside returns `:no_nav_found` and the install
  task prints manual instructions instead. **Unbounded `</ul>` search could corrupt host layouts.**
  The first `</ul>` *anywhere after* the `<nav>`/`<header>` open is used —
  a header with no `<ul>` plus a footer link list gets kit links injected
  into the footer, and the patch reports `:patched` success. Bound the
  search to the enclosing element's close tag, else return `:no_nav_found`.

### Generators

- [x] **DONE (0.3.0).** **`joby_kit.new` router template breaks variant flags**
  (`priv/templates/joby_kit.new/router.ex:32-40`). Unconditional
  `import Phoenix.LiveDashboard.Router` + Swoosh mailbox `forward`, but the
  task advertises forwarding `--no-dashboard` / `--no-mailer` — those
  generate apps that don't compile. Template needs conditional sections (or
  the task refuses those flags).
- [x] **DONE (0.3.0).** **`add_joby_kit_dep` fails silent on regex miss**
  (`lib/mix/tasks/joby_kit.new.ex:236-256`). If the `defp deps do` regex
  doesn't match, the file is written unchanged and "* updating mix.exs" is
  still printed; failure surfaces later as a confusing compile error. Verify
  the dep actually landed and raise otherwise.
- [x] **DONE (0.3.0).** **Bootstrap home template models the anti-pattern the kit polices**
  (`priv/templates/joby_kit.bootstrap/home_live.ex:43-71`). Hand-rolled
  `card card-bordered` / `btn btn-primary` raw markup instead of `<.card>` /
  `<.button>` — and `card-bordered` is a daisyUI 4 class removed in v5
  (dead class; v5 name is `card-border`). The `joby_kit.new` home template
  does this correctly — port it.
- [x] **DONE (0.3.0).** **`gen.wrapper`'s fresh composite file can't compile real composites**
  (`lib/mix/tasks/joby_kit.gen.wrapper.ex:153-172`). When it creates
  `composite_components.ex` from scratch it uses bare `use Phoenix.Component`
  — no `~p`, no kit imports — while the install template uses
  `use <App>Web, :html`. A composite composing `<.icon>` or routes won't
  compile. Align with the install template.

## Consumer feedback — consolidated (orchester · airo · mem_pal, 2026-08-10)

Structured feedback from three fleet consumers, cross-checked against the
0.2.2 source (their line refs were 0.2.0/0.2.1; refs below are current).
Overlapping themes are adopted outright. Single-consumer items were weighed
against this audit's own findings — accepted, deferred, and the reasoning
noted inline.

The organizing insight (orchester's phrasing, supported by usage data from
all three apps): **adoption is inversely proportional to baked-in opinion.**
button/input — shape + behavior, no spacing opinions — get hundreds of
uses; card/header/list — typography + margin opinions — get bypassed.
Orchester: 127 hand-rolled panels vs 10 `<.card>` uses. mem_pal: 0 uses of
`<.header>` and `<.list>`, with the hand-rolled header class string
copy-pasted 10×.

### C1 — Components style beyond their border (3/3 apps + this audit) → **DONE (0.3.0)**

The single biggest theme; every documented escape traces to it. Verified
in current source:

- [x] **DONE (0.3.0).** **`<.input>` root margin is unreachable** — all four variants render
  `<div class="fieldset mb-2">` (`core_components.ex:486,514,535,552`)
  while `class` and `:rest` land on the *inner control*
  (lines 520/541/560). This violates the kit's own "class is additive on
  the root" contract (the moduledoc promises it; button/card/table honor
  it). Documented fallout: orchester's composer passes `class="mb-0"` and
  it silently does nothing; mem_pal's Create button carries a `mb-0.5`
  magic-number nudge that still misaligns; filter rows fight the margin
  with their own `gap`. Also hardcoded `w-full` with no width control.
  Fix: `class`/`:rest` target the root, add `input_class` for the control,
  drop `mb-2` (or `spacing="none"`), and add a `bare`/`wrapper={false}`
  mode (would have prevented orchester's raw-textarea escape).
- [x] **DONE (0.3.0).** **`<.card>` forces body typography** — inner_block wrapped in
  `text-sm leading-relaxed text-base-content/70` (line 166) with no
  opt-out (`class` goes on the root, not the wrapper); actions hardcode
  `mt-3` (line 169). Because inner_block is one div, card-body's `gap-2`
  is dead weight — mem_pal hand-adds `mb-4`/`mt-1` four times in one
  file. Fix: `body_class` or `variant="plain"`, or render inner_block as
  direct card-body children so the gap works.
- [x] **DONE (0.3.0).** **`<.header>` bakes `pb-4` and nails the type scale** (line 193;
  h1 fixed at `text-lg font-semibold`). Both header-consuming apps
  hand-roll every page header instead.
- [ ] *(still to write)* **Adopt as a kit principle** (document in AGENTS.md + CLAUDE.md
  templates): no external margins on component roots — parents own
  spacing via `gap`/`space-y`; no typography opinions on slot content;
  where an internal wrapper is genuinely needed, expose a class hook.
- [x] **DONE (0.3.0).** **Changelog obligation when this lands** — `MIGRATING-0.3.md` leads with the hack-removal table.: hosts carry compensating
  hacks (mem_pal's `mb-0.5` nudge, gap-fights) that become *wrong* once
  the margins are removed — the release notes must list the hacks to
  delete, per the fork/changelog convention in C4.

## P2 — correctness and API polish

### Core components

- [x] **DONE (0.3.0).** `table` stream ergonomics: doc example crashed when
  followed with a stream — the `:let` receives `{dom_id, item}` tuples, not
  items. Either document the tuple shape + `row_item` unwrap, or default
  `row_item` to unwrap streams. Also `attr :rows, :list` (line 252) is wrong
  for half the API (streams) — `:any` + doc is honest.
- [ ] `table`: required `id` lands on `<tbody>` not `<table>` (line 285), so
  hosts can't id the table element at all; no `overflow-x-auto` wrapper
  (daisy's responsive pattern); `<th>` without `scope="col"`.
- [x] **DONE.** `input type="file"` silently drops `multiple` (line 448 vs 521): it's a
  declared attr only rendered in the select branch; the `:rest` include-list
  entry is dead code. File pickers can't multi-select.
- [x] **DONE (0.3.0).** `input`: errors not associated with the control — no `aria-describedby`
  / `aria-invalid`; daisy 5's `validator`/`validator-hint` exist for this.
  Root is `div.fieldset` instead of semantic `<fieldset>` + `fieldset-legend`.
- [x] **DONE (0.2.3) for the role; enum still open.** `flash`: `role="alert"` for `:info` interrupts screen
  readers ("Saved" is `role="status"` material); `values: [:info, :error]`
  (line 319) locks out `:warning`/`:success` hosts entirely; whole-toast
  click-dismiss breaks silently if a host passes `phx-click` via `:rest`.
- [ ] `button`: runtime-computed variant outside the enum crashes with a bare
  `KeyError` (lines 92-93 `Map.fetch!`); no name for the default soft style
  in the enum, so dynamic callers must pass nil.
- [x] **DONE.** `icon`: non-`hero-` name raised `FunctionClauseError` with no helpful
  message; caller `class` replaces (not merges) the `size-4` default; no
